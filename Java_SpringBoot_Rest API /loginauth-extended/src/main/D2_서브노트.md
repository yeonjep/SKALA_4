# Day 2 서브노트: 스프링 부트 없이 순수 자바로 만든 로그인·회원가입 서버 분석

**SKALA 4반 박연제**

학습목표: 회원가입·로그인·회원 인증 기능을 스프링 부트(Spring Boot) 프레임워크 없이 오직 자바(Java) 언어와 표준 라이브러리(com.sun.net.httpserver.HttpServer, java.sql 등)만으로 서버(SimpleAuthServer.java)구현하기. 스프링이 제공하는 자동화 도구 없이 HTTP 요청 처리부터 라우팅, 인증, DB 연동까지 전 과정이 자바 코드만으로 어떻게 구성되는지 확인하는 예제.

## Chapter 1. 실습 목표와 진행 절차

### 1. 실습 목표

> 요약: 스프링 부트 없이 오직 자바 언어와 표준 라이브러리만으로 구현된 완성 코드를 직접 실행해보고, 회원가입·로그인·로그인 상태 유지 기능이 순수 자바 코드만으로 어떻게 동작하는지 코드 분석을 통해 이해하는 것

### 2. 진행한 절차

1. 제공받은 SimpleAuthServer.java의 DB_URL 포트 확인 및 수정 (교수님 예시 포트 53301 → 내 컨테이너 실제 포트 3379)
2. ./gradlew build로 빌드 → 컴파일 및 테스트 정상 통과 확인
3. ./gradlew run으로 서버 실행 → "Server started at http://localhost:8080" 확인
4. /signup 페이지에서 회원가입 → /login으로 리다이렉트되는 것 확인
5. MySQL Workbench에서 users 테이블 조회 → BCrypt 해시로 저장된 것 확인
6. /login 페이지에서 동일 계정으로 로그인 → 로그인 성공 확인

### 3. 결과

회원가입한 계정으로 로그인까지 정상 동작하는 것을 확인함. DB에는 항상 BCrypt 해시 값만 남고, 로그인 이후에는 세션·JWT 쿠키로 로그인 상태를 판별.

## Chapter 2. 스프링 없이 자바만으로 구현된 부분 분석 (SimpleAuthServer.java)

스프링 부트가 제공하는 기능 없이, 서버 구동부터 라우팅·인증·DB 연동까지 순수 자바 언어와 JDK 표준 API만으로 구현됨.

### 1. 서버 구동 - java.com.sun.net.httpserver.HttpServer

스프링 부트에서는 내장 톰캣이 띄워줄 웹 서버를 이 코드는 JDK에 포함된 HttpServer 클래스를 이용해 자바 코드로 직접 생성·구동.

- main()에서 HttpServer.create()로 8080 포트에 서버를 열고, 스레드풀(Executors)을 직접 만들어 서버에 연결하는 부분까지 전부 자바 표준 라이브러리 코드로 작성
- 객체 간의 연결(JdbcUserRepository → AuthService)도 스프링 컨테이너 없이 main() 안에서 자바 코드로 순서대로 생성해 넘겨주는 방식(수동 DI)

### 2. 요청 라우팅 - server.createContext

스프링의 @GetMapping·@PostMapping 같은 어노테이션 기반 라우팅 대신 server.createContext(경로, 핸들러) 메서드를 자바 코드로 하나씩 호출해 /, /login, /signup, /api/signup, /api/login, /api/auth/check, /home.html, /api/logout 등 모든 경로를 매핑.

- 각 경로의 처리 로직은 HttpHandler를 구현한 자바 람다식으로 작성되어 요청 URL을 판별하고 그에 맞는 자바 메서드를 실행하는 구조 자체가 전부 자바 코드로 구성.

### 3. 회원가입 흐름 (/api/signup)

회원가입 요청 처리: 프레임워크 없이 자바 코드로 처리

- HttpExchange에서 요청 바디를 읽어 parseFormBody() 메서드로 아이디·비밀번호를 직접 문자열 파싱함. 스프링의 @RequestParam 같은 자동 바인딩이 아닌 순수 자바 문자열 처리 코드로 값을 추출
- AuthService.signUp() 호출 시 BCrypt.hashpw(rawPassword, BCrypt.gensalt(12))로 비밀번호를 해시하고, JdbcUserRepository.save()가 java.sql.PreparedStatement로 users 테이블에 INSERT 문을 직접 실행. ORM 없이 순수 JDBC 코드로 작성.
- 성공 시 redirect() 메서드가 /login으로 리다이렉트하며, 아이디 중복 시에는 try-catch로 에러 메시지 응답

### 4. 로그인 흐름과 로그인 상태 유지 (/api/login)

스프링 시큐리티의 세션 관리 기능 없이 모두 자바 클래스로 구현함.

- AuthService.login()에서 findByUsername()으로 저장된 해시를 조회하고 BCrypt.checkpw(rawPassword, hashedPassword)로 검증함. 해시 복호화가 아닌 입력값을 재해시해 비교하는 단방향 검증 방식으로, Day 1의 평문 비교를 개선한 형태
- 로그인 상태를 기억하는 저장소는 ConcurrentHashMap(SESSION_STORE)을 직접 구현해 세션 ID와 사용자 정보를 저장. 스프링 세션 관리 대신 자바 컬렉션 클래스로 구현
- JwtUtil 클래스에서 JWT.create()로 만료 1시간짜리 토큰을 HMAC256으로 서명해 발급. auth0 JWT 라이브러리를 자바 코드에서 직접 호출하는 방식으로 구현.

### 5. 로그인 상태 확인과 로그아웃

- /api/auth/check 핸들러는 세션 쿠키와 JWT 쿠키를 둘 다 검사하는 이중 확인 로직을 자바 조건문으로 구현 (resolveSessionId, JwtUtil.verifyToken)
- /api/logout는 SESSION_STORE에서 세션을 제거하고 쿠키 세 종류를 만료시키는 처리를 자바 메서드 호출로 수행

### 6. 계층 구조도 자바 클래스 설계로 직접 구성

스프링의 @Entity, @Repository, @Service 같은 어노테이션 없이, User(POJO) / UserRepository·JdbcUserRepository(DB 접근) / AuthService(비즈니스 로직)로 역할이 나뉜 계층 구조를 순수 자바 인터페이스와 클래스만으로 설계함.

- UserRepository를 인터페이스로 두고 JdbcUserRepository가 이를 구현하는 방식 -> DB 접근 방식 변경 시 구현체 클래스만 교체하면 됨

## Chapter 3. 자바만으로 구현했을 때 드러나는 특징

- 경로 하나가 추가될 때마다 createContext 호출이 자바 코드에 하나씩 늘어나는 구조 -> 라우팅 전체가 코드 분량에 비례해 증가
- DB 커넥션을 요청마다 자바 코드에서 새로 열고 닫음 -> 연결 관리 로직을 프레임워크 없이 직접 관리해야 하는 구조
- 로그인 세션이 자바 프로세스 메모리(ConcurrentHashMap)에만 존재 -> 서버 재시작 시 로그인 상태 함께 소멸
- DB 주소·JWT 시크릿 값 등 설정값이 소스 코드 안에 상수로 고정 -> 포트 하나만 바꾸려 해도 자바 파일 직접 수정 필요
- 응답 JSON도 자바 문자열을 직접 이어붙여 생성(writeJson) -> 필드가 많아질수록 형식 관리가 까다로움
