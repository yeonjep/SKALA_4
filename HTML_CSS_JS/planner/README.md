# SKALA 스터디 플래너

SKALA 프로그래밍 기초(HTML·CSS·JavaScript) 과정 최종 제출 과제로 제작한 학습 목표 관리 웹 애플리케이션입니다.

---

## 1. 구현한 기능 목록

### 1.1 필수 기능 (F1~F7)

| 번호 | 기능              | 구현 내용                                                                                                            |
| ---- | ----------------- | -------------------------------------------------------------------------------------------------------------------- |
| F1   | 목표 추가         | 제목·마감일이 비어 있거나 공백만 입력된 경우 등록을 거부하고, 브라우저 기본 유효성 메시지(`reportValidity()`)로 안내 |
| F2   | 완료 토글 · 삭제  | 목록(`#goal-list`)에 이벤트 리스너 1개만 등록하고 `closest()`로 대상을 판별하는 이벤트 위임 방식으로 구현            |
| F3   | 필터 · 진행률     | 전체/진행중/완료 탭 필터, 완료 개수와 비율(%)을 함께 표시                                                            |
| F4   | localStorage 저장 | 목표를 추가·수정·삭제·완료 처리할 때마다 `localStorage`에 저장하여 새로고침 후에도 목록 유지                         |
| F5   | 마감일 입력       | `input type="date"`로 마감일을 필수 입력받고, 마감일이 지난 미완료 목표는 빨간색으로 시각적으로 강조                 |
| F6   | 검색              | 검색창에 입력하는 즉시(`input` 이벤트) 제목에 해당 문자열이 포함된 목표만 필터링                                     |
| F7   | 분류별 요약       | 분류(HTML/CSS/JS)별 남은(미완료) 목표 개수를 집계하여 텍스트로 표시                                                  |

### 1.2 화면 품질 요구사항 충족 내역

- 시맨틱 태그(`header`, `main`, `section`, `footer`)로 문서 구조 구성
- 모든 입력 요소에 `label`을 `for`/`id`로 연결(시각적으로는 `sr-only` 처리)
- 색상·간격 등 디자인 토큰은 `:root`의 CSS 커스텀 프로퍼티로 정의해 재사용
- 클래스명은 단일 하이픈 규칙 준수(예: `item-check`, `btn-primary`)
- 레이아웃은 Flexbox 기반으로 구성(요소를 임의로 띄우는 방식 미사용)
- 사용자 입력은 `innerHTML`에 그대로 삽입하지 않고 `escapeHtml()`을 거쳐 XSS 방지

### 1.3 도전 과제 (선택 구현, 5개 전부 구현)

- **목표 제목 수정**: 제목 더블클릭 시 입력창으로 전환되어 즉시 수정 가능(Enter 저장 / Esc 취소)
- **정렬**: 기본 / 마감임박순 / 최신순 정렬 버튼(원본 배열은 변경하지 않고 복사본만 정렬)
- **다크모드**: 라이트/다크 테마 전환 및 `localStorage` 기반 테마 유지
- **빈 화면 안내 문구**: 등록된 목표가 없을 때 안내 문구와 입력 예시 표시
- **추가/삭제 애니메이션**: 목표 추가 시 등장 트랜지션, 삭제 시 퇴장 트랜지션 적용

### 1.4 추가 구현 사항 (자율)

- **다크모드 스위치 UI**: 기존 버튼 방식을 iOS/Android 스타일의 온오프 스위치로 교체
- **오늘의 팁 캐러셀**: `data/tips.json`을 `fetch()`로 비동기 로드하여 무작위 3개를 추출, 하단 점(dot) 인디케이터와 함께 4초 간격 자동 슬라이드 및 좌우 드래그(포인터 이벤트) 전환 지원

## 2. 실행 방법

### 2.1 폴더 구조

```
박연제_스터디플래너/
├─ index.html
├─ css/
│  └─ style.css
├─ js/
│  └─ app.js
├─ data/
│  └─ tips.json
└─ README.md
```

### 2.2 실행 절차

1. VS Code에서 프로젝트 폴더를 연다.
2. Live Server 확장 프로그램을 설치한다(미설치 시).
3. `index.html`을 우클릭 → **Open with Live Server**를 실행한다.
4. 브라우저 주소창이 `http://127.0.0.1:5500/...` 형태인지 확인한다.

> **주의**: `index.html`을 더블클릭해서 여는 방식(`file://` 프로토콜)은 사용하지 않는다. "오늘의 팁" 기능이 `fetch()`로 로컬 JSON 파일을 읽어오는데, `fetch()`는 `file://` 환경에서 동작하지 않아 반드시 Live Server(`http://`)로 실행해야 한다.

## 3. 어려웠던 점과 해결

### 3.1 다크모드 스위치 UI 구현

**문제**: 기존 버튼 형태의 다크모드 토글을 온오프 스위치 형태로 교체하는 과정에서, HTML 마크업(체크박스 + 슬라이더용 `span`)만 변경하고 관련 CSS를 완전히 반영하지 못해, 실제로는 브라우저 기본 체크박스가 그대로 노출되는 문제가 발생했다.

**해결**: 체크박스 자체는 `opacity: 0`으로 화면에서 감추고, 인접 형제 선택자(`input:checked + .theme-switch-slider`)를 이용해 체크 상태에 따라 슬라이더의 배경색과 손잡이(`::before`) 위치를 CSS `transition`으로 애니메이션 처리하는 방식으로 재구현했다. HTML과 CSS를 함께 검토해 두 파일이 실제로 일치하는지 재확인한 뒤 문제를 해결했다.

### 3.2 오늘의 팁 캐러셀 슬라이딩 구현

**문제**: 처음에는 하단 점(dot)을 클릭해야만 슬라이드가 전환되었고, 박스를 손으로 잡아 좌우로 끄는 방식(드래그/스와이프)은 동작하지 않았다. 또한 슬라이드 컨테이너에 `overflow: hidden`, `display: flex` 등 레이아웃 관련 CSS가 누락되어, 점 인디케이터가 서로 붙어 보이고 슬라이드가 옆으로 자연스럽게 넘어가지 않는 문제도 함께 있었다.

**해결**: 먼저 `.tip-slider`에 `overflow: hidden`, `.tip-track`에 `display: flex`를 적용해 슬라이드 3개가 가로로 나란히 배치되고 그중 1개만 보이도록 레이아웃을 바로잡았다. 이어서 `pointerdown` / `pointermove` / `pointerup` 이벤트를 이용해, 포인터(마우스·터치 공통)가 눌린 지점부터 이동한 거리를 계산하여 그만큼 슬라이드를 실시간으로 따라오게 만들고, 손을 뗀 시점에 이동 거리가 슬라이더 폭의 20%를 넘으면 다음/이전 슬라이드로 확정, 넘지 않으면 원래 위치로 스냅되도록 구현했다. 퍼센트 단위 대신 픽셀 단위로 이동량을 계산해 드래그 거리와 슬라이드 위치를 같은 기준으로 다룬 것이 해결의 핵심이었다.
